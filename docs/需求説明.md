# 需求說明（V2）

## 1. 根本目的
建立一套適合「1 人 + 多 AI（Codex / Claude / Gemini）」的自動化協作流程：
- 任務可由遠端聊天入口（Telegram Bot，後續可擴 Slack）或本地操作觸發。
- 任務可在已打開的 VSCode/CLI AI 會話中被分發執行。
- 執行過程與結果可被持續追蹤、回寫、再通知給人或其他 AI。

## 2. 已確認約束
- Telegram Bot 運行在遠端服務器/同一服務器可運行redis。
- MySQL 運行在雲服務器（另一雲）。
- 本地機器運行多個 AI CLI（Codex / Claude / Gemini）與分發/橋接程序。
- 網路拓撲以「本地主動連雲端」為主，避免雲端主動連入本地（NAT/防火牆風險）。

## 3. 目標架構（最終採用）
採用「雲端 MySQL 中樞 + 本地 AI Worker 主動拉取（pull）」：
1. 遠端 Telegram Bot 收到消息後，寫入雲 MySQL `ai_tasks`。
2. 本地 `dispatcher.py` 輪詢雲 MySQL，抓取 `pending` 任務並標記為 `dispatching`。
3. `dispatcher.py` 根據 `ai_target` 投遞到對應 `window_bridge.py`（本地端口路由）。
4. `window_bridge.py` 將消息送入對應 AI CLI（互動模式或 exec 模式）。
5. AI 執行後，通過 `ai_feedback.py` 回寫中間結果/最終結果/追問到雲 MySQL `ai_feedback`。
6. 遠端 Telegram Bot 消費 `ai_feedback`，推送回手機端。
7. 人類在 Telegram 回覆後，Bot 再次寫入 `ai_tasks`，形成閉環。

## 4. 設計原則
- 簡潔優先：先保證單人可穩定運作，再考慮複雜擴展。
- 單一派發真實來源：跨機部署時以 MySQL 任務表為主，避免多入口重複消費。
- 可追蹤：任務與回覆都可按 `task_id` 關聯與審計。
- 可恢復：任何單節點重啟後可從 MySQL 狀態續跑。

## 5. 核心組件
- 本地：
  - `dispatcher.py`：任務拉取、狀態流轉、路由分發。
  - `window_bridge.py`：AI CLI 橋接，按 AI 名稱映射端口。
  - `ai_feedback.py`：AI 回寫工具（中間結果/最終結果/提問）。
  - `matrix_ui.py`：本地控制台與觀測入口（可選）。
- 遠端：
  - `telegram bot service`：消息入口/出口，與 MySQL 交互。

## 6. 數據模型與狀態流轉
### 6.1 任務表 `ai_tasks`
建議狀態：
- `pending`：待分發
- `dispatching`：已鎖定，準備投遞
- `running`：已送達 AI，執行中
- `waiting_human`：等待人工回覆
- `completed`：已完成
- `failed`：執行失敗

建議關鍵欄位：
- `id`, `ai_target`, `message`, `status`, `priority`
- `idempotency_key`（去重鍵，避免重複任務）
- `created_at`, `updated_at`, `dispatched_at`, `finished_at`
- `last_error`

### 6.2 回饋表 `ai_feedback`
建議欄位：
- `id`, `task_id`, `source_ai`, `channel`, `payload`, `created_at`
- `channel` 建議值：`progress | result | ask | system`

## 7. 任務路由規則
- `ai_target=claude -> 9001`
- `ai_target=gemini -> 9002`
- `ai_target=codex -> 9003`
- 未知 `ai_target`：標記 `failed` 並記錄 `last_error`。

## 8. Redis 的定位（跨機情境）
- Redis 不再作為跨機主入口。
- 可作為本地快取、短期事件緩衝、UI 顯示輔助。
- 跨機權威數據以雲 MySQL 為準。

## 9. 安全與運維要求
- 所有資料庫連線配置改為環境變數，不在代碼中硬編碼密碼。
- 雲 MySQL 啟用 TLS（至少傳輸加密）。
- MySQL 使用最小權限帳號（bot / dispatcher / feedback 分帳號）。
- IP 白名單限制來源地址。
- 關鍵日誌留存：分發日誌、橋接日誌、Bot 收發日誌。

## 10. 任務1（現況）
`matrix_ui.py` 已完成初步能力：
- 可接入本地輸入，並查看最近任務/輸出。
- 任務和反饋可落 MySQL。
- 與 `dispatcher.py + window_bridge.py + ai_feedback.py` 可形成最小閉環。

待補齊：
- 雲端 Telegram Bot 對 `ai_tasks/ai_feedback` 的收發閉環。
- `idempotency_key` 去重與更完整狀態流轉（`running/waiting_human/completed`）。

## 11. 驗收標準（MVP）
- 人在 Telegram 發任務，60 秒內本地指定 AI 開始執行。
- AI 可至少回寫 1 條進度與 1 條最終結果到 MySQL。
- 手機端可收到最終結果。
- 人工在 Telegram 回覆可再次觸發後續任務。
- 同一 `idempotency_key` 不被重複執行。
