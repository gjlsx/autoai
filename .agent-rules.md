# Agent Rules

Follow `.agent-rules.md` before any action.

## to build a tasklist, must read the tasklist_rules.md 
## to run a task in tasklist, must read the tasklist_rules.md 

## 0. Core Principles
- Read rules first, then read tasklist, then execute.
- Use Markdown files as the primary source of truth.
- Important information must be documented.
- Skills are passive documentation under `skills/`.
- External tools belong under `mcp/` if added later.
- Executor can hold only **one active lock** at a time.
- Review is **self-review**.
- Memory is split into:
  - global memory index
  - project-specific memory
- AI should read only:
  - global memory index
  - its current project's memory

## 1. Allowed Files to Modify or start a task  only if 1,2,3,4 below:
  1- its own task log under `tasks/<agent>/`
  2 - its own lock under `tasks/locks/ainame_taskid.lock` ,
  3 - and there is no other `ainame.taskid.lock` file in /tasks/locks/   
   means if there is file `B.taskid.lock` in the dir ,Then ai A can't do this task,
  4 - allowed status fields in `tasklist.md` or input `taskxxx.md` file!

- code/tests/docs directly required by the claimed task

## 2. Forbidden Actions
Executor must NOT:
- create new tasks
- change tasklist table structure
- modify other agent logs
- modify other agent locks
- modify global memory structure unless acting as Scheduler/Human
- mark task as `done` without passing tests

## 3. Startup Sequence
1. read `.agent-rules.md`
2. read `tasklist.md`  or input 'taskxxx.md' file!
3. read `memorys/global.md`
4. read current project memory if the task belongs to a project
5. scan `tasks/locks/` for your own lock using filename pattern: `<agent name>_<taskid>.lock`
6. if your own lock exists:
   - inspect related task status in `tasklist.md`  or input `taskxxx.md` file!
   - if task is already `done` or `cancelled`, delete the lock
   - otherwise resume that task directly
7. if no active own lock exists, find first matching `todo` task for your role
8. check dependencies
9. create lock
10. claim task
11. execute
12. run tests
13. self code review
14. if refactor is needed, repeat execute -> test -> self review until no refactor is needed
15. update tasklist
16. remove lock

## 4. Locked Task Rule
- Lock is never taken over by another AI.
- Each AI scans only its own lock.
- Lock filename format looks like : '(ai's name)_taskid.lock` ,
  - `codex_t0316.p10.lock`  
  - `claude_t0316.p11.lock`

- One AI can have only one lock at a time.
- If an AI already has an unfinished lock task, it must continue that task first.

## 5. Claim Rule
When claiming a task, update only allowed tasklist fields:
- `Owner`
- `Status`
- `Claim`
- `Finish`
- `Report`
- `Git`
- `Review`
- `Score`

Claim format:
`startat:YYMMDDHHMMSS <agent> tasks/<agent>/<taskid>.md`

## 6. Execution Loop
If the task is already claimed by the current AI, do NOT restart the full claiming flow.
Go directly to:
1. execute
2. run tests
3. self code review
4. if refactor needed, repeat execute -> tests -> self review
5. update tasklist
6. remove lock

## 7. Testing Rule
A task cannot become `done` unless required tests pass.
Examples:
- `pytest`
- `npm test`
- `go test ./...`
- project-specific minimal verification command

If no tests exist, add at least minimal validation or document manual verification evidence.

## 8. Self Review Rule
Review is self-review only.

Required checks:
- requirement satisfied
- tests passed
- no obvious duplicate logic left unhandled
- naming consistent
- no required refactor remains
- task log is complete

Review outcomes:
- `pass:no-refactor-needed`
- `pass:minor-refactor-done`
- `partial:needs-followup`

## 9. Definition of Done
A task is `done` only when all are true:
- implementation complete
- required tests passed
- self review says no further necessary refactor
- task log written
- tasklist updated
- lock removed

## 10. Task Status Set
Allowed statuses:
- `todo`
- `doing`
- `blocked`
- `partial`
- `pending`
- `done`
- `cancelled`

## 11. Dependency Rule
Before claiming a `todo` task, check `Depends`.
If any dependency is not `done`, skip the task.

## 12. Memory Read Rule
Memory root is `memorys/`.

Use:
- `memorys/global.md` for global rules and project memory links
- `memorys/<project-name>/memory.md` for project-specific memory

Do not read unrelated project memory unless explicitly required.
